# 데이터베이스 설계

## 1. 설계 기준

본 프로젝트의 데이터베이스는 배전반 제작 흐름을 `견적 -> 수주 -> 호기 -> 공정 -> 검사/시험 -> 이력` 순서로 추적하기 위해 설계했다.

핵심 기준은 다음과 같다.

- DN 번호는 수주 번호가 아니라 실제 제작 단위인 호기 번호로 관리한다.
- 하나의 수주는 여러 호기를 가질 수 있으므로 `orders`와 `units`는 1:N 관계로 둔다.
- 공정명과 순서는 `process_masters`에 관리하고, 실제 진행 상태는 `unit_processes`에 저장한다.
- 재고는 구매 수량과 현재 수량을 분리해 입고 당시 수량과 잔량을 함께 관리한다.
- LOT 정보는 재고 단위에 저장하고, 수주 자재는 사용 재고를 참조한다.
- 진행 중인 견적은 AI 전환 확률을 반영해 2주 내 예상 자재 소요량에 포함한다.
- AI 배선 검사는 실제 비전 모델이 아니라 mock 결과를 DB에 저장하고 대시보드와 이력 추적에 반영한다.

## 2. 주요 테이블

| 테이블 | 역할 |
| --- | --- |
| `customers` | 고객사와 고객 등급 관리 |
| `quotes` | 진행 견적, 견적 단계, 예상 납기, AI 전환 확률 관리 |
| `orders` | 확정 수주 정보 관리 |
| `units` | 수주에서 생성된 호기 정보 관리 |
| `process_masters` | 표준 공정 순서와 기준 소요일 관리 |
| `unit_processes` | 호기별 공정 진행 상태와 실적 관리 |
| `materials` | 자재 마스터와 리드타임 관리 |
| `inventories` | 자재 LOT별 구매 수량, 현재 수량, 입고일 관리 |
| `order_materials` | 확정 수주별 필요 자재 관리 |
| `quote_materials` | 진행 견적별 예상 필요 자재 관리 |
| `ai_inspections` | AI 배선 검사 mock 결과 관리 |
| `tests` | 시험 성적 기록 관리 |
| `events` | 통합 관제 최근 이벤트 관리 |

## 3. 테이블 상세

### customers

| 컬럼 | 설명 |
| --- | --- |
| `id` | 고객 ID |
| `name` | 고객사명 |
| `grade` | 고객 등급. `A`, `B`, `C`, `N` 사용 |
| `created_at` | 등록 시각 |

`N`은 등급 미정 고객을 의미한다.

### quotes

| 컬럼 | 설명 |
| --- | --- |
| `id` | 견적 ID |
| `customer_id` | 고객 ID |
| `item_name` | 견적 품목 |
| `quantity` | 예상 수량 |
| `expected_due_date` | 예상 납기 |
| `quote_stage` | 견적 단계 |
| `estimated_amount` | 견적 금액 |
| `probability` | 전환 확률 |
| `status` | 진행, 전환, 실패, 보류 상태 |
| `created_at` | 등록 시각 |

견적 입력 시 AI 모델이 전환 확률을 계산하고, 보수 계산값을 `probability`에 저장한다.

### orders

| 컬럼 | 설명 |
| --- | --- |
| `id` | 수주 ID |
| `customer_id` | 고객 ID |
| `quote_id` | 연결된 견적 ID |
| `item_name` | 수주 품목 |
| `quantity` | 수주 수량 |
| `due_date` | 납기 |
| `status` | 대기, 진행중, 완료, 지연주의, 자재발주중 |
| `created_at` | 등록 시각 |

견적에서 실제 수주로 전환된 경우 `quote_id`로 연결한다.

### units

| 컬럼 | 설명 |
| --- | --- |
| `id` | 호기 ID |
| `order_id` | 수주 ID |
| `unit_no` | 호기 번호. 예: `DN-2608-023` |
| `item_detail` | 호기 상세 |
| `status` | 호기 상태 |
| `created_at` | 등록 시각 |

화면에서 검색하고 이력을 추적하는 기준 값은 `unit_no`이다.

### process_masters

| 컬럼 | 설명 |
| --- | --- |
| `id` | 공정 ID |
| `name` | 공정명 |
| `sequence` | 공정 순서 |
| `standard_days` | 표준 소요일 |

현재 공정은 다음 8단계로 관리한다.

1. 설계
2. 설계 확정
3. 판금 절곡
4. 도장
5. 부스바 조립
6. 배선
7. 검사 시험
8. 출하 대기

### unit_processes

| 컬럼 | 설명 |
| --- | --- |
| `id` | 호기 공정 ID |
| `unit_id` | 호기 ID |
| `process_master_id` | 공정 마스터 ID |
| `started_at` | 공정 시작 시각 |
| `completed_at` | 공정 완료 시각 |
| `status` | 대기, 진행중, 완료, 지연주의 |
| `result_quantity` | 실적 수량 |
| `is_rework` | 재작업 여부 |

납기 위험은 완료되지 않은 공정의 표준 소요일 합계와 납기까지 남은 기간을 비교해 계산한다.

### materials

| 컬럼 | 설명 |
| --- | --- |
| `id` | 자재 ID |
| `name` | 자재명 |
| `unit` | 단위 |
| `lead_time_days` | 리드타임 |

### inventories

| 컬럼 | 설명 |
| --- | --- |
| `id` | 재고 ID |
| `material_id` | 자재 ID |
| `lot_no` | LOT 번호 |
| `purchased_quantity` | 구매 수량 |
| `current_quantity` | 현재 수량 |
| `received_at` | 입고일 |

구매 수량은 입고 당시 기준값이고, 현재 수량은 소모에 따라 변하는 값이다.

### order_materials

| 컬럼 | 설명 |
| --- | --- |
| `id` | 수주 자재 ID |
| `order_id` | 수주 ID |
| `material_id` | 자재 ID |
| `required_quantity` | 확정 수주 필요 수량 |
| `inventory_id` | 사용 재고 ID |

### quote_materials

| 컬럼 | 설명 |
| --- | --- |
| `id` | 견적 자재 ID |
| `quote_id` | 견적 ID |
| `material_id` | 자재 ID |
| `required_quantity` | 견적 기준 예상 필요 수량 |

진행 견적의 필요 수량은 `quotes.probability`를 곱해 예상 소요량에 반영한다.

### ai_inspections

| 컬럼 | 설명 |
| --- | --- |
| `id` | AI 검사 ID |
| `unit_id` | 호기 ID |
| `inspection_type` | 검사 유형 |
| `result` | `PASS` 또는 `FAIL` |
| `confidence` | 판독 신뢰도 |
| `finding` | 검출 내용 |
| `read_seconds` | 판독 소요 시간 |
| `inspected_at` | 검사 시각 |

### tests

| 컬럼 | 설명 |
| --- | --- |
| `id` | 시험 ID |
| `unit_id` | 호기 ID |
| `test_item` | 시험 항목 |
| `measured_value` | 측정값 |
| `criteria` | 기준값 |
| `result` | `PASS` 또는 `FAIL` |
| `tester` | 시험자 |
| `tested_at` | 시험 시각 |

### events

| 컬럼 | 설명 |
| --- | --- |
| `id` | 이벤트 ID |
| `unit_id` | 호기 ID |
| `event_type` | 이벤트 유형 |
| `message` | 이벤트 메시지 |
| `severity` | `info`, `warning`, `error` |
| `occurred_at` | 발생 시각 |

## 4. 주요 관계

| 관계 | 설명 |
| --- | --- |
| `customers 1:N quotes` | 고객은 여러 견적을 가질 수 있다. |
| `customers 1:N orders` | 고객은 여러 수주를 가질 수 있다. |
| `quotes 1:N orders` | 견적이 수주로 전환될 수 있다. |
| `orders 1:N units` | 하나의 수주에서 여러 호기가 생성될 수 있다. |
| `units 1:N unit_processes` | 호기별로 공정 진행 이력을 가진다. |
| `process_masters 1:N unit_processes` | 표준 공정을 호기별 공정 이력에서 참조한다. |
| `materials 1:N inventories` | 하나의 자재가 여러 LOT 재고를 가진다. |
| `orders 1:N order_materials` | 확정 수주별 필요 자재를 관리한다. |
| `quotes 1:N quote_materials` | 진행 견적별 예상 필요 자재를 관리한다. |
| `units 1:N ai_inspections` | 호기별 AI 검사 이력을 관리한다. |
| `units 1:N tests` | 호기별 시험 성적을 관리한다. |
| `units 1:N events` | 호기별 이벤트를 관리한다. |

## 5. 마이그레이션

| 파일 | 내용 |
| --- | --- |
| `001_create_schema.sql` | 기본 테이블 생성 |
| `002_quote_forecast_schema.sql` | 견적, 견적 자재, 고객 등급, 수주-견적 연결 추가 |
| `003_fix_customer_grade_check.sql` | 고객 등급 `N` 허용 |
